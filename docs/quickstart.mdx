You need Docker. That is all for the first path; the second runs the app from
source, for working on it.

## With Docker only

```bash
git clone https://github.com/pwnera/artbucket.git
cd artbucket
cp .env.example .env
# Set BETTER_AUTH_SECRET in .env: openssl rand -base64 32
docker compose --profile app up -d
```

This starts Postgres, S3-compatible storage (SeaweedFS) and the app, which
migrates its database as it starts. Open http://localhost:3000.

## From source

You need Node 22 or later and pnpm.

```bash
git clone https://github.com/pwnera/artbucket.git
cd artbucket
pnpm install
cp .env.example .env
docker compose up -d      # Postgres and storage only
pnpm dev
```

## Make the first account

Open http://localhost:3000 and make an account. The first one is the admin of
everything, and until it exists nothing else works, in the app or the API.
Then drop in a file.

The first time an admin opens the library, it asks, over the whole page,
what they want to do: manage their company's brand and assets, create a
brand for an open-source project, manage brands for clients, build a brand
and a design system for a product, or give AI agents the brand. Each answer
is a short list that ends in its first win (a released brand, the brand in
public, a client workspace, the brand in a Git repository, an agent's first
MCP call), with connecting a Git repository where it fits, and each step
checks itself off once it is done. Skipped or unfinished, the list stays
at the top of the library.

Optional extras for previews: `ffmpeg` on the path for video thumbnails (the
Docker image has it), and LibreOffice (`soffice`) for Word, Excel and
PowerPoint previews beyond the thumbnail a file was saved with.
