title: MCP
description: One URL connects every agent.
---

`/api/v1/mcp` is an MCP server over Streamable HTTP, running the same logic as the
REST API. Chat apps (Claude, ChatGPT, Perplexity, Gemini), coding agents, app
builders (Lovable, v0, Bolt, Replit) and Figma take the URL and send you to a
consent screen, where you pick the workspaces it works in and what it may do
there: Suggest, Read or Edit. What it gets is a key bound to you: never more
than you can do, and gone with your access. The Connections page has the setup
for each, and changes an agent's workspaces and access later without it signing
in again.

An agent given several workspaces names one with `workspace` on any tool (its
slug, or `organization/slug` when two share one); without it, the tool runs in
the first one picked. The server's instructions list them.

```bash
claude mcp add --transport http artbucket https://assets.example.com/api/v1/mcp
```

That is OAuth 2.1 with PKCE and dynamic client registration, discovered from
`/.well-known/oauth-protected-resource`. Keys an admin makes still work for
anything headless (n8n, Make, scripts): `Authorization: Bearer ab_...`.

A tool shows up in `tools/list` only when the key may run it: the portal
tools, only for a key that may manage portals (write on the workspace, with
sharing not turned off).

Brands, collections, custom fields, reviews, brand history, comments and
portals (passwords and branding included) are run over MCP as in the app.
A collection is named by its id or its name; `list_collections` gives the ids that `ingest_asset`,
`import_icons` and `create_portal` take.

Brand rules are also resources: `artbucket://brand/rules`, and
`artbucket://brands/{slug}/rules/{context}`. So is every brand page, as
Markdown: `artbucket://brands/{slug}/pages/{page}`.

## Brand pages

A brand's guidelines are pages laid out over its rules. An agent builds them
with the same tools a person's edits go through, and starts with
`brand_status`: the same steps the builder and the brand's Overview show, in
order (colors, typefaces, logo, voice, look, pages, published, shared), each
step with whether it is done, how an agent does it, and the `points` it adds to
the Brand Agent Score (`score`, of 100). `next` is the step to take now. Ask
again after a change. Before the first page, read `brand_playbook`: what a good brand
site is, and a worked example in calls. The [playbook](/guides/playbook) is the
same text.

1. **Rules are the content.** `set_rules` writes many at once. A rule's `label`
   is the heading readers see; its key never changes. Its `spec` holds what the
   value can't: a color's print values, tints, the color set on it, or a
   gradient (`spec.gradient`, whose stops name color rules, with the rule's
   `value` as the solid fallback), a number's unit, a face's role, tracking and case.
2. **Pages are the layout.** `list_templates` says what each template shows,
   binds and lists, with an example. `save_page` writes a page whole: `parent`
   nests it (three levels at most), and each section binds rules by `keys`.
   `items` hold what a template lists, like a do or a don't with its picture.
   `tone` picks a section's ground: `plain`, `tint`, `brand`, `panel`, `dark`,
   `color` and `image` (set in `background`), or `pattern` (the theme's device).
   A page's `layout` is `book`, a chapter with the nav beside it (the default),
   or `landing`, a front for a home or campaign page with no nav column,
   on-this-page or pager.
3. **The theme is the look.** `set_theme` says which rules play which part
   (accent, grounds, ink, faces, logo) and sets the measure and chrome: radius,
   width, density, type scale, navigation, numbering, motion. It merges, and
   `null` clears a setting back to what the rules give.
4. **Check before publishing.** Every page write, and `get_page`, returns
   `warnings` (a link to no page, a key with no rule) and `url`, the page in the
   app as readers will see it.
5. **Publish when asked.** Edits are drafts. `publish` takes a `note` for
   readers (up to 2000 characters) and an `image` beside it; portals show the
   publish, never the draft, and `portals` in its answer names where.
6. **Put it in front of people.** `create_portal` makes a portal: `name`, the
   `brands` (by slug) and `collections` (by id) it shows, and `access`:
   `members`, `password` (with the `password` the person gives you) or
   `public`; ask the person before a public one. `theme` sets its logo (an
   approved image asset), accent and background; `domain`, one of the
   organization's verified domains. Its `slug` comes from the name when left
   out. `list_portals` says which portals show which
   brands, and whether each brand was ever published (`publishedAt: null`:
   visitors see nothing of it). `update_portal` takes the portal's slug and
   what changes: `brands` and `collections` (each the whole list, in order),
   `access` and `password`, `theme` (a setting left out stays; `null` clears
   it), `expiresAt`, and `site`, which replaces the whole set, so send back
   what `list_portals` gave, changed. People who ask to get into a password or
   members portal wait in `list_portal_requests`; `decide_portal_request`
   answers them.
7. **Review and history.** `list_comments` reads what reviewers said on the
   pages; `add_comment` replies and `update_comment` resolves a thread once it
   is dealt with. Every edit is a version: `list_versions` and `get_version`
   read the history, and `restore_version` brings an earlier one back as a new
   version, so a restore can be undone the same way.

`edit_page` changes a page an operation at a time. Its `page` operation sets
the page's own fields; a new `slug` renames it, and the old slug stays an alias,
so links and `get_page` still find it. A page with pages under it can't be
deleted until they move.

A font rule's `spec.download: false` hides the download buttons from readers.
It is not protection: the files are still served, because the pages set their
text in them through `@font-face`.

## The skill

`npx skills add pwnera/artbucket` installs a skill that teaches an agent the
workflow: brand rules first, `check_use` before publishing, provenance on
anything generated. In Claude Code, the plugin brings the MCP server and the
skill together:

```bash
/plugin marketplace add pwnera/artbucket
/plugin install artbucket@artbucket
```

Its server is Artbucket Cloud. On your own server, start Claude Code with
`ARTBUCKET_URL=https://your-server`.
